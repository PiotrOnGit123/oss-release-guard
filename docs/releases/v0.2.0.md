# v0.2.0 - Maintainer Workflow Release

OSS Release Guard now supports the work around a release as well as the archive audit itself: issue triage, PR review, release readiness, and grouped release notes.

Published on 2026-10-09: [GitHub release and four verified assets](https://github.com/PiotrOnGit123/oss-release-guard/releases/tag/v0.2.0), [successful publication run](https://github.com/PiotrOnGit123/oss-release-guard/actions/runs/37894134275), and [closed release milestone](https://github.com/PiotrOnGit123/oss-release-guard/milestone/2).

## Changes

- Added `triage-issue`, `review-checklist`, `release-readiness`, and `release-notes` commands in [PR #1](https://github.com/PiotrOnGit123/oss-release-guard/pull/1).
- Added maintainer process docs, issue forms, and review checklists in [PR #2](https://github.com/PiotrOnGit123/oss-release-guard/pull/2).
- Added repository quality gates in [PR #3](https://github.com/PiotrOnGit123/oss-release-guard/pull/3), version metadata in [PR #4](https://github.com/PiotrOnGit123/oss-release-guard/pull/4), and Python 3.10 compatibility in [PR #13](https://github.com/PiotrOnGit123/oss-release-guard/pull/13).
- Hardened input validation and release decisions; added Ruff, Bandit, dependency auditing, coverage, example checks, packaging checks, and Dependabot in [PR #15](https://github.com/PiotrOnGit123/oss-release-guard/pull/15).
- Added verified release publication, canonical labels, and actual GitHub milestones in [PR #18](https://github.com/PiotrOnGit123/oss-release-guard/pull/18).
- Diagnosed publication API permissions in [PR #19](https://github.com/PiotrOnGit123/oss-release-guard/pull/19) and granted milestone assignment permission only to the verified publisher in [PR #20](https://github.com/PiotrOnGit123/oss-release-guard/pull/20).

## Compatibility

The archive audit invocation and exit codes remain available. Maintainer JSON commands now reject duplicate keys, invalid UTF-8, non-finite numbers, files over 1 MiB, and nesting beyond 32 levels. Release readiness requires a version and blocks secret-like field names. Numeric `1` is no longer treated as a boolean confirmation. Invalid input exits `2`; an unmet release requirement exits `1`. Breaking changes have their own release-notes section.

## Quality And Security

- Final regression suite: 74 tests passed; branch-aware runtime coverage: 92%. The initial hardening PR had 64 tests; publisher boundary tests expanded that suite before publication.
- Linux/Windows matrix: Python 3.10, 3.12, and 3.14.
- Ruff lint/format, Bandit, and strict pip-audit checks passed; coverage must remain at least 85%.
- Runtime uses the Python standard library; development tools and the build backend are pinned and audited.
- The publication workflow reruns the full CI gates, validates wheel/source distributions with Twine, audits both archive formats, and smoke-tests the installed wheel outside the source checkout.
- Assets include a wheel, source distribution, `SHA256SUMS`, and `artifact-audit.json`.

## Follow-Up Maintenance

At publication, Dependabot's major [setup-python update #16](https://github.com/PiotrOnGit123/oss-release-guard/pull/16) and [checkout update #17](https://github.com/PiotrOnGit123/oss-release-guard/pull/17) were reviewed and deferred. The follow-up audit subsequently approved and merged both updates across CI and publication under [issue #22](https://github.com/PiotrOnGit123/oss-release-guard/issues/22), and included them in the v0.2.1 patch preparation. They are not changes to the v0.2.0 source tag or assets. These are real automated dependency proposals, not simulated human contributions.

See the [changelog](https://github.com/PiotrOnGit123/oss-release-guard/blob/main/CHANGELOG.md), [security policy](https://github.com/PiotrOnGit123/oss-release-guard/blob/main/SECURITY.md), and [release process](https://github.com/PiotrOnGit123/oss-release-guard/blob/main/docs/release-process.md). Release preparation and milestone completion are tracked in [issue #8](https://github.com/PiotrOnGit123/oss-release-guard/issues/8).

This is an early pre-release. The readiness manifest records caller declarations; it does not authenticate them or query live CI. Field-name checks are not a complete secret scanner. Archive metadata checks do not prove extraction safety or publisher identity. Checksums published with the artifacts establish consistency; obtain and authenticate release provenance independently for high-trust use. External adoption has not been measured.
