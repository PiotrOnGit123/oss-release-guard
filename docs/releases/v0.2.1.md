# v0.2.1 - JSON Overflow Validation Fix

This patch corrects the maintainer JSON loader in [PR #25](https://github.com/PiotrOnGit123/oss-release-guard/pull/25) and publishes a new snapshot without replacing v0.2.0 artifacts.

Published on 2026-10-09: [release and four uploaded assets](https://github.com/PiotrOnGit123/oss-release-guard/releases/tag/v0.2.1), [successful verification/publication run](https://github.com/PiotrOnGit123/oss-release-guard/actions/runs/37979848886), and [closed v0.2.1 milestone](https://github.com/PiotrOnGit123/oss-release-guard/milestone/4). Source commit: `b1ad0335ce7f06c4067d8ec0be9e71e7c469f44b`.

## Fixed

- Reject positive, negative and nested exponent overflow such as `1e309`. Previously, JSON's float conversion could produce infinity even though literal `NaN` and `Infinity` were already rejected. Tracked in [issue #23](https://github.com/PiotrOnGit123/oss-release-guard/issues/23).
- Keep error output static: all four maintainer commands exit `2` without a traceback or input contents when a non-finite number is encountered.
- Preserve ordinary finite floats, large finite exponents, and integer handling. Archive-audit behavior and valid manifest gates are unchanged.

Compatibility tracking [#22](https://github.com/PiotrOnGit123/oss-release-guard/issues/22) records the upstream review and successful combined main CI.
- Preserve read-only PR tests, non-persisted checkout credentials and post-verification publication permissions.
- Generalize the explicit release merge marker to `[publish-release]`; the reviewed package metadata selects the tag. Existing tags and assets are never moved or overwritten.

## Quality And Security

- 77 regression tests passed locally; branch-aware runtime coverage is 92%, above the 85% gate.
- Three new tests cover signed/nested overflow, finite-number compatibility, and all four CLI failure paths.
- Full publication gates cover Linux/Windows on Python 3.10, 3.12 and 3.14, Ruff lint/format, Bandit, dependency auditing, example consistency, strict package checks and archive audits.
- The publisher verifies and exercises the installed wheel outside the source checkout before releasing four assets: wheel, source distribution, `SHA256SUMS` and `artifact-audit.json`.

This remains an early pre-release. The defect is confirmed input-validation behavior, not an established code-execution or credential-disclosure vulnerability. Readiness inputs are caller declarations; key-name checks are not a complete secret scanner. Archive audits and published checksums do not prove extraction safety or independent publisher authenticity. External adoption and independent human review have not been established.
