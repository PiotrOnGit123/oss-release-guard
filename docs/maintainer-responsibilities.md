# Maintainer Responsibilities

Maintainers are responsible for more than accepting code. They protect release quality, user trust, and the public record of project decisions.

## Core responsibilities

- Triage issues with labels, priority, and a clear next action.
- Review pull requests for correctness, tests, documentation, security, and release impact.
- Keep CI, tests, and local quality gates healthy.
- Maintain `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, and process docs.
- Prepare releases with notes, quality evidence, and known limitations.
- Handle vulnerability reports carefully and avoid public disclosure of sensitive details.

## Release manager role

The release manager owns the target version checklist, milestone state, release notes, and final readiness decision. They should confirm that unresolved blockers are either fixed or explicitly deferred.

## Security contact role

The security contact handles vulnerability intake, reproduction, impact assessment, private coordination, and safe disclosure notes. Public issues should avoid exploit archives, credentials, and private data.

## Review rotation role

The review rotation keeps pull requests moving. It can request changes, close stale work with explanation, or escalate security and release-impact changes to the appropriate maintainer.
