# Code of Conduct

OSS Release Guard uses the Contributor Covenant as a baseline for respectful participation. The project is small, but maintainers still expect contributors to keep discussion focused, kind, and useful.

## Expected behavior

- Be respectful when reporting bugs, reviewing pull requests, and disagreeing about policy.
- Assume good intent while still asking for evidence, tests, and clear threat models.
- Keep security-sensitive details out of public issues until maintainers confirm a safe disclosure path.
- Prefer concrete examples, reproducible cases, and actionable review comments.

## Unacceptable behavior

- Harassment, personal attacks, or demeaning language.
- Publishing credentials, private data, exploit payloads, or confidential reports in public threads.
- Repeatedly pushing unrelated arguments into issue or release discussions.
- Misrepresenting identity, affiliation, review status, or maintainer approval.

## Enforcement

Maintainers may edit, hide, lock, or remove comments that create safety or disclosure risk. They may also pause review on a pull request until the conversation returns to the technical issue. Serious or repeated violations can result in blocking from the project.

Report conduct concerns through a private maintainer channel when available. If no private channel is available, open a minimal public issue asking maintainers to establish one without including sensitive details.
